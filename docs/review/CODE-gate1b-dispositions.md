# Gate 1b — dispositions

Review: [CODE-gate1b-gpt.md](CODE-gate1b-gpt.md) (GPT-6 Astra, advisory only), 2026-10-23, at `0b57bb3`. Fixes: commit `474c307` (Rust) and the analysis commit that follows it. Every item is either fixed, with its evidence, or accepted as a stated limitation.

## Critical residual paths

| Item | Disposition | Evidence |
|---|---|---|
| **R1** Expiry barrier from inconsistent backends could release a landed fee | **Fixed by design change.** RPC non-inclusion evidence never releases a fee. An expired transaction frees its payer (`expired_charged`), but its worst-case fee stays charged. The only release is a stream that was provably never opened. The frozen design's worst case (0.039 SOL) fits under the 0.05 SOL cap by itself. The barrier itself now takes slot and height from one finalized `getBlock` answer. Landings an RPC missed are caught by the verifier's completeness check over archived window blocks. | `ledger.rs` (`expire_charged`, `CHARGED_FEE_SQL`, test `expiry_frees_the_payer_but_never_the_fee`); `rpc.rs::finalized_barrier`; `verify.py::completeness` (test `test_a_probe_in_a_window_block_without_its_landing_claim_fails_completeness`) |
| **R2** Balanced double loss certifies a false rule | **Fixed as an identification statement.** The selection assumption is stated as an assumption, not as "checked". The balance test is a partial test only. Worst-case bounds now cover every pair of the evaluable windows, single- *and* neither-landed. Each rule verdict carries `selection_robust`, and a non-robust claim is published as "R (assumes selection)". The counterexample is a unit test and an OC scenario (`balanced_double_loss`, POWER.md); it is never selection-robust. | PREREGISTRATION §1; `stats.py::selection_bounds`, `selection_robust`; `report.py::published_claim`; test `test_balanced_double_loss_is_flagged_as_not_selection_robust` |
| **R3** Deadlines did not bound actual writes | **Fixed.** One absolute stop instant, `min(--not-after, start + --max-minutes)`, clamps every scheduled send. `open_uni` runs under `timeout_at(deadline)`. A stream opened after its deadline is reset unwritten. The write has a fixed 50 ms grace, and once a stream is open the reservation is kept whatever happens. Live runs require `--not-after`. | `quic.rs::send_scheduled`; `run.rs` (`stop_at_ns`, phase checks) |

## New findings

| Item | Disposition | Evidence |
|---|---|---|
| **N1** Manifest fails open; pilot data admitted | **Fixed.** `--manifest` is explicit; a requested missing file is an error. Without a manifest nothing is confirmatory. With one, runs must match the design and genesis, use the campaign budget, start after `frozen_at` and before `not_after`, and not be excluded. | `report.py::load_manifest`, `select_runs`; test `test_a_requested_manifest_that_does_not_exist_is_an_error` |
| **N2** Realised treatment never validated against the frozen design | **Fixed.** Every window's realised probes must equal its frozen plan (pair ids and kinds, labels, templates, positions, locks). The check runs against the design whose hash the run recorded; otherwise the window is `design_mismatch` or `design_unavailable`. Send evidence is checked per probe, and duplicate records exclude the window. `itb design` validation also binds each label to its library template, checks the exact label set per pair kind and checks the lock structure. | `outcomes.py::window_table`, `_send_evidence`; `design.rs::validate`; test `test_a_template_swapped_behind_its_label_is_a_design_mismatch` |
| **N3** Positive controls pass after selection failure; withdrawal invisible | **Fixed.** A control passes only with the final verdict `reward_cost` (after the selection override and the strictness split) in its frozen direct-ingress group. A failure withdraws every other group's *published claim*, and the summary prints published claims plus a withdrawal banner. | `report.py` (§9 block, `published_claim`, `markdown_summary`); test `test_published_claims_carry_every_withdrawal` |
| **N4** Client/ingress partitioning expands the family | **Fixed.** The manifest freezes one (client, ingress) group per core target. Only that group is confirmatory; any other observed group is labelled exploratory and kept out of Holm. | `scripts/freeze.py`; `report.py::analyse` (`confirmatory`) |
| **N5** Pilot progress leaks into the campaign | **Fixed.** Journal records carry the mode, the design hash and the budget (purpose). Loading filters on all three, and only one terminal record per window counts. | `run.rs::load_progress`; test `progress_is_bound_to_mode_design_and_purpose_and_counts_each_window_once` |
| **N6** Recovery loses measurement evidence | **Fixed.** Reservations store provenance (run, probe, target, window). `itb reconcile` writes each outcome (marked `recovered`) and each landing-block excerpt into the original run, and journals restored windows with zero informative pairs: recovery can only extend sampling. Analysis takes the last outcome record per probe. | `ledger.rs` (`Provenance`), `recover.rs`, `load.py::_flatten_outcomes`; test `cap_leases_and_provenance_survive_restart` |
| **N7** Lock and leases only protect `run` | **Fixed.** `campaign::Campaign` is shared by `run`, `smoke`, `setup` and `reconcile`, and `ledger --add-deposit-lamports` takes the lock too. It is an OS file lock, released by the OS on process death. Fund and sweep refuse while any owned account has an unresolved transaction. | `campaign.rs`; test `campaign_lock_is_exclusive_and_released_on_drop` |
| **N8** Failed reconciliation does not stop other sends; tolerance not charged | **Fixed.** Reconciliation has no tolerance. An unexplained drop is charged as a ledger adjustment, which reduces headroom, and sets a process-wide stop checked before every reservation. Every live command reconciles before sending. Every send needs a budget with a defined cap. | `ledger.rs::reconcile`, `charge_adjustment`; `campaign.rs::reconcile_now`, `ensure_running`; tests `reconciliation_has_no_tolerance`, `adjustments_reduce_headroom`, `sub_budget_is_enforced_and_an_undefined_budget_is_refused` |
| **N9** "Achieved offset" was an estimate | **Fixed.** The offset is measured from the observed first-shred event of the target's first slot in the run's slot-event archive (createdBank for localnet runs). Windows without that event are counted as unavailable; no estimated anchor is substituted. | `report.py::_achieved_offsets` |
| **N10** Strictness counted unobserved predictions | **Fixed.** Only complete windows are scored, i.e. windows where every contrast with one of the rule's directional predictions was observed. Incomplete windows are counted. | `stats.py::strictness`; test `test_strictness_is_scored_only_on_complete_windows` |
| **N11** OC validated a different procedure | **Fixed.** OC applies the stopping predicate `itb run` uses (`stop_informative`). It then scores the published claim from `report.analyse`, the same function as the report, so design validation, grouping, the strictness split, selection, controls and buffer gates are all included. The simulator injects failed streams, unproduced windows and gossip transitions. The positive controls follow reward/cost in every scenario. Family-wise error is reported with its exact 95 % upper bound, plus a separate "robust wrong" rate. | `oc.py`, `sim.py`; POWER.md |
| **N12** Missing attribution accepted or crashing | **Fixed.** The used endpoint and both snapshots must carry a complete attribution, or the window is `mode:unknown`. A change, including leaving gossip, is `mode:transition_ambiguous`. There are no string conversions of missing values. | `outcomes.py::_gossip_mode`; `test_outcomes.py` |
| **N13** Extra serialised signature accepted | **Fixed.** The signature count must equal 1 and match the header, the complete on-chain signature vector must equal the signed one, and the ComputeBudget instructions must take no accounts. | `verify.py::check_atom`, `check_onchain_message`; test `test_an_extra_serialised_signature_is_rejected` |
| **N14** Judge-facing claims exceed the implementation | **Fixed.** PLAN's inference and spend-cap prose is replaced by pointers to PREREGISTRATION. The 200 ms and 3–6 s lifetime claims are replaced by the observed cadence and block-height validity. The H comment is corrected to −7 s and the dual-RPC promise is removed. The README states the review status and links this file. | `docs/PLAN.md`, `README.md`, `design.rs` |
